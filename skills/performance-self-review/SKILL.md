# 绩效自评：先取证，再写个人贡献

## 启动与来源边界

先用一组简短问题补齐会改变结果或权限的信息；用户已给出的内容直接复用，不重复追问：

1. 考核起止日期、项目或专项、本人角色，以及绩效系统要求的产出数量、栏目层级、篇幅、数字详略和语气是什么？哪些场景或能力需展开，哪些仅作背景？“做得好的”和“需要继续努力的”分别聚焦什么，是否需要行动计划？
2. 历史 Codex 会话（含归档）、钉钉文档、钉钉聊天记录各有哪些入口？分别已收集到什么范围，还允许读取哪些内容？聊天记录若已暂停收集，只使用已有材料。
3. 有哪些历史自评、项目文件、业务验收、经营回执或用户最终录入文本可参考？哪些只是背景，哪些可证明本期结果？

这三类历史资料是主要输入，不预设 DWS、某个连接器、固定目录或单一检索命令。根据用户给出的入口、当前可用能力与权限选读取方式；先复用已取得的资料。新增聊天读取须在用户授权的范围内。遇到认证、权限或内容缺失，记录阻断与已覆盖部分，不把失败解释成零结果。

## 证据台账先行

在写自评前，建立可回查的来源覆盖记录和事项台账；现有台账可增量更新。对每一类来源分别记录发现范围、去重后的候选数、取得正文或消息数、实际核读范围、失败项和未展开范围。索引命中、正文取得与用于自评是不同层级；不能用一个层级的数量代替另一个。

每项事项至少保留：考核期内发生日期、项目与目标、本人职责和动作、团队或他人动作、已验证结果、指标口径及统计窗口、源链接或本地定位、证据类型、当前状态和未知项。将用户自述、文档分工、本人消息、系统回执及业务验收分别标明；重复资料合并到同一事项，不按会话数或自动化运行次数折算贡献。

数字先核对时间窗口、分母、粒度和同口径的新旧版本。优先使用考核期内最新且可复核的结果；只有旧值时注明日期与用途，或不在正式自评中写数。目标、估算、团队账单和历史自评数字不能冒充本人期末业绩。对矛盾或缺少回执的结果保留 `partial`、待验证或明确的证据缺口，不用推断补齐。

证据等级影响表达力度，不等于一律删掉信息。考核期内有可回查的本人消息或业务方反馈时，可用“据该次评测反馈”“我向业务转述”等方式保留重要数字，并注明统计日期；缺少原始实验表、完整分母或显著性检验的限制记入台账，不把转述升级为独立验收或期末实时数据。用户明确确认的定性结果可作为本人复盘判断，独立验收缺失另行标明；对结果的原因单独评估，用户的因果解释不能自动视为已证实。

影响同一判断的对照指标、覆盖条件或目标量应关联表达，压缩篇幅时不只留下其中一部分。文档的成文/更新时间不能替代指标的统计发生期；发生期不明的数字留作背景或待核，不写成本期最新结果。

## 写作与归因

- 按用户确认的数量、层级、详略和范围组织成稿；这些是本次输入，不固定为技能模板。用户需要角色、行动、结果等栏目时保留层级，需要短段落时自然合并。用户未要求计划时，不强制补未来动作。
- 业务工作按项目或专项的推进逻辑写：业务问题 → 本人职责与关键动作 → 可核验阶段结果与采用状态。避免按月份、客户名单或沟通次数罗列。
- 工具与能力工作按“解决的问题 → 建设的能力 → 验证结果 → 当前适用边界”写。区分本地验证、生产运行、外部通知和业务采用。
- 明确区分方案交付、试点执行、业务验收、生产修复、规模化应用与经营结果。团队规模、团队交付量或他人实现不得写成本人独立产出；协同贡献可准确写成需求拆解、推动和反馈。
- 本人建议或规范的目的，与已验证的改善分开写。缺少后续效果时用“旨在、建议、明确”等准确动作，不写成已经减少故障、成本或等待。仅有团队资料和总角色时，不据此补认领某项具体执行；工具局部验证也不能代替其后续处理、交付或采用环节的验收。
- 最后按用户要求写综合自评，各段维持约定的聚焦范围。通常“做得好的”提炼有证据的结果和可复用做法；“需要继续努力的”写结果缺口、原因和本人反思。仅在用户或系统栏目要求时加入行动计划。不强写“超预期”。
- 用户修改并最终录入的文本优先作为措辞与结构参考；它本身不自动证明其中每个业务事实。未经请求，不覆盖最终录入文本或把旧草稿当成最终版。

从台账到正文时，优先保留能证明本人贡献的具体信息：关键数字或需求量、验证口径、调用/处理边界、问题定位和实际改造。不要把这些压缩为泛泛的“协同、建设、沉淀”，也不要用一般团队进展替代个人关键动作。需求量可作为本人澄清的需求写入，但始终区分目标与实现。

详略服从本次篇幅约定。先在台账或内部提纲中按产出列出所选的业务对象、本人动作、关键数字/条件和状态，再分配篇幅；成稿后核对这些核心事项是否真的写入正文，不能以“台账已经有了”代替正文覆盖。默认以关键结果指标及影响判断的重要条件、需求量为主；一般团队规模、样本规模、测试通过数量、阶段预算和旁支目标留在台账。用户需要展现实施规模或详细案例数据时，再按其栏目取舍。正文不重复整份量化台账。相关但不同的验证对象或动作应区分，例如数据质量检查与业务增益评测不能相互替代。补足来源线索后再判断是否缺少内容，不用措辞要求补造没有证据的动作。

成稿后对照用户约定和事项台账核对：重点场景、重要数字与具体动作是否遗漏或被其他内容替代，两段反思是否自行扩大范围。核对含义与事实，不要求逐字一致。正文保留影响理解的来源限定和状态边界；详细取证缺口、索引数量及未读项放证据台账或附注，避免正文被验收语言占据。

用户给出明确篇幅限制时，按约定的计数口径实际核对拟交付正文；没有指定口径则采用明确说明的字符数，包含正文中的中英文与标点，不混入台账或缺口附注。超限时在核心内容覆盖提纲内压缩并复核，而不是删去关键动作、数字或边界。没有篇幅限制时无需为计数增加步骤。

交付适合系统录入的正文、可追溯证据台账及覆盖缺口说明。保留用户指定的本地落点；发布、发送和写入绩效系统须有对应授权。共享技能本身只保存通用方法和匿名示例，不保存个人绩效、原始聊天、内部文档正文或敏感指标。
