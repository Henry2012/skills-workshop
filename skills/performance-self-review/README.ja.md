# performance-self-review

**成果を書く前に、その根拠をたどる。**

[English](README.md) · [简体中文](README.zh-CN.md) · [ホーム](../../README.ja.md)

大量の仕事の記録から、検証しにくい実績文を作ってしまうことがあります。この Skill は、まず資料の取得・確認範囲と証拠台帳を作ります。

**本人の行動、チームの納品物、採用・検証された結果**を区別します。目標は実績ではなく、同僚が実装した修正は本人の実装成果ではありません。伝聞の数値は、出典、日付、制約を示せば参考情報として保持できます。

**入力**は評価期間、本人の役割、必要な形式、利用権限のある資料。**出力**は自己評価文、追跡可能な台帳、資料の不足範囲です。

## 最小例

Agent に本ディレクトリの `SKILL.md` と `examples/self-review/input.md` を読み、与えた資料だけで「成果」と「振り返り」の短い 2 段落、別添の証拠台帳と不足範囲を作るよう依頼します。外部サービスへの接続や公開は行いません。

[参照出力](../../examples/self-review/output.md)と比較し、架空の担当者による受け入れ基準の設計と障害調査を、同僚による実装や未確認の本番復旧と分けているか確認します。`python3 tools/check.py` でコミット済みの例の要点を検査できます。

## 依存関係と限界

貼り付けた文章やローカル文書だけで利用できます。会社のアカウント、チャット連携、特定の保存先、他の Skill は不要です。追加取得には適切なツールと許可が必要で、取得できない資料は不足として記録します。

公開するのはルールと明確に架空とした例だけです。実際の文書、チャット、自己評価、台帳は非公開リポジトリなど別の場所で管理してください。閲覧許可は公開や人事システムへの書き込み許可ではありません。

証拠に基づく文章も、与えられた資料の統合にとどまります。業務採用、因果関係、評価等級を独立して証明するものではありません。
