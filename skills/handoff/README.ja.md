# handoff

**セッションが変わっても、仕事の境界を保つ。**

[English](README.md) · [简体中文](README.zh-CN.md) · [ホーム](../../README.ja.md)

長い会話には、決定、却下した案、過去のコマンド、異なる意味の「完了」が混在します。この Skill は、次の Agent が続行に必要な状態を引き継ぎ書にまとめます。

**現在の目的**と**最新の依頼**を分けることが重要です。途中の質問だけで目的が置き換わることを防ぎます。完了の主張には証拠と検証範囲を添え、既存の許可を保持しつつ、過去のコマンドは実行指示として扱いません。

**入力**は会話、現在の指示、成果物、検証結果。**出力**は 13 の固定見出し、未確認事項、引き継ぎ時の最初の行動を含む `HANDOFF.md` です。

## 最小例

ルートで `python3 tools/demo_handoff.py` を実行します。小さなオフラインテストを実行し、実際のローカルパスを使った参考ファイルを `build/handoff/` に生成します。LLM は呼び出しません。

[シナリオ](../../examples/handoff/scenario.md)を読み、Agent にこのディレクトリの `SKILL.md`、シナリオ、`build/handoff/test-result.json` から `build/handoff/AGENT_HANDOFF.md` を作るよう依頼してください。実際の絶対パスを使い、範囲を保持し、デプロイや完了済み作業の再実行を禁止します。

テストの成功を本番稼働の証明にしていないか、次のセッションが読み取りと要約から始め、既存の許可の範囲で文書作業を続けるかを確認します。

## 依存関係と限界

Agent が会話と関連ファイルを読める必要があります。デモのみ Python 3.10 以降を使用します。アカウント、API キー、ネットワーク、他の Skill は不要です。記録されていない事実は復元できません。

固定見出しは中国語のままです。本文の言語は指定できます。実際の引き継ぎにはパスや業務情報が含まれるため、そのまま公開しないでください。
