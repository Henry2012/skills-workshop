# Skills Workshop

**後から検証でき、次の Agent に引き継げる仕事のための Skills。**

[English](README.md) · [简体中文](README.zh-CN.md)

Agent の回答は完成しているように見えても、元の目的を見失ったり、一部の確認を全体の成功と扱ったり、チームの成果を個人の実績として書いてしまうことがあります。このリポジトリでは、そのような問題を具体的な作業ルールに落とし込みます。

Henry2012 が AI と協働して開発した、指示ベースの Skills です。セッションの引き継ぎ、設計レビュー、証拠に基づく自己評価、意味を保持する技術文書の編集を扱います。各 Skill に架空の例があり、自分の Agent で試して結果を確認できます。

## 問題から選ぶ

| 困っていること | Skill | 特徴 |
|---|---|---|
| 会話が長くなり、新しいセッションへ移りたい | [handoff](skills/handoff/README.ja.md) | 目的、範囲、証拠、既存の許可を保持。過去のコマンドを勝手に再実行しません。 |
| 設計が実装に進める状態か判断したい | [reviewing-design-documents](skills/reviewing-design-documents/README.ja.md) | 欠落、不要な重複、矛盾、誤り、曖昧さ、実現性、検証方法、失敗への対応を 8 つの問いで確認。 |
| 仕事の記録から自分の貢献を整理したい | [performance-self-review](skills/performance-self-review/README.ja.md) | 先に証拠台帳を作成。本人の行動、チームの成果、目標、検証済みの結果を区別します。 |
| 技術文を読みやすくし、意味も保ちたい | [simplify-tech-writing](skills/simplify-tech-writing/README.ja.md) | 条件、数値、用語、不確実性を保持。HTTP 200 を「復旧済み」に変えません。 |

[8 つの問いの紹介](skills/reviewing-design-documents/README.ja.md)では、API、製品公開、業務手順への適用例を示します。問いは共通でも、証拠と合格基準は判断対象ごとに決まります。

モデルを学習させる仕組みでも、バックグラウンドサービスでもありません。Agent がすべての指示に従う保証はありません。

## まず試す

Git が必要です。ローカルチェックには Python 3.10 以降を使います。

```sh
git clone https://github.com/Henry2012/skills-workshop.git
cd skills-workshop
python3 tools/check.py
```

リポジトリを開いた Agent に、次のように依頼します。

> `skills/reviewing-design-documents/SKILL.md` と必須の rubric を読んでください。`examples/design-review/design.md` が実装を開始できる状態か、読み取り専用でレビューし、日本語で報告してください。

[参照レビュー](examples/design-review/review.md)と比較してください。「成功」の定義の矛盾を見つけ、両方の記述を示し、1 つの根本原因として扱えているかが確認点です。

例は架空の入力を使った解説です。ローカルチェックはファイルと例の要件を検証しますが、LLM を実行せず、モデルの精度も測定しません。[検証範囲](docs/VALIDATION.md)を参照してください。

## 自分のプロジェクトで使う

まず `SKILL.md` と参照ファイルを読み、Agent が対象ディレクトリにアクセスできる状態で Skill を明示的に指定します。ネイティブな Skill 検出に対応するツールでは、そのツールの手順に従って `skills/` 内の個別ディレクトリをインストールしてください。相対参照を保ち、既存の同名 Skill を確認せず上書きしないでください。

紹介文は英語・中国語・日本語で用意しています。実行時の指示は元の英語・中国語と固定ラベルを保持しています。本文は希望する言語で依頼できますが、`handoff` の固定見出しは中国語のままです。

設計をレビューし、許可された作業を進め、状態を次のセッションに引き継ぎ、貢献を証拠から整理できます。これは組み合わせ方の例であり、自動接続済みのパイプラインではありません。レビュー結果自体が実行許可になることはありません。

## 出典と参加方法

4 つのワークフローは Henry2012 と AI の協働によるものです。課題の選択、制約、受け入れ基準、利用に基づく改善を人が担い、AI が文章化、パッケージ化、検証を支援しています。技術文書の Skill は ASD-STE100 からの着想を明記し、規格自体は配布しません。実質的に変更していない他者の Skill は作品として収録しません。

再現可能な不具合、最小限のルール変更、既存動作を壊していないことが分かる例を歓迎します。業務チャット、個人の評価資料、認証情報、内部 URL は投稿しないでください。
